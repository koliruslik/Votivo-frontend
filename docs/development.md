# Development notes

The Angular shell supplies navigation, account state and lazy routes. `AuthService` loads `/auth-config.json` before routing the login callback, maintains reactive session state and delegates account actions to the pinned Keycloak adapter. Tokens are not persisted by application code. Configuration loading has a five-second timeout; adapter initialization and token refresh each have an eight-second deadline so an unresponsive identity provider cannot leave bootstrap or an API request pending indefinitely. Late callbacks from a rejected session cannot restore the displayed account.

`PollService` owns typed REST calls and maps expected failures to user-facing messages. It uses `AuthService.request`, which permits same-origin `/api/v1/` requests only and calls the adapter's `fetch` method for authenticated requests. This preserves DPoP support instead of adding an unbound Bearer interceptor. Share tokens learned through `/s/:token` remain in service memory and are attached only to that poll's vote/result requests.

The feature components implement the list, editor and detail/result views. Server pagination remains authoritative. Text and status filters affect only the loaded page; the UI labels that scope. Poll and vote permissions come from API contracts. Route guards and hidden controls provide navigation convenience; backend authorization remains mandatory.

The editor tracks unsaved changes for both in-app navigation and tab closure. Saving disables its fields and in-app navigation; a failed save retains the edits, and explicitly reloading a dirty draft asks for confirmation. Draft route changes discard stale fetch responses. Publishing, closing, blocking, archiving, withdrawing and deleting require a native modal confirmation. Voting waits for participation status, requires every question and disables duplicate submission while a request is pending. After publication the page reloads participation status before enabling voting. A 404 from Vote Service means its poll projection is not available, not that the user has never voted; the UI keeps voting disabled and offers retry. Session expiry also disables the ballot.

Results are an asynchronous projection. A successful vote does not imply its counts are already visible; the UI explains the delay and offers refresh. Percentages use total ballots as the denominator, so multiple-choice percentages may sum above 100%.

`server/index.mjs` serves static assets and routes an allowlisted set of API paths. Poll endpoints go to Poll Service, `/vote` to Vote Service, `/results` to Result Service. `server/auth.mjs` verifies JWT and DPoP with `jose`. The server forwards the verified access token to Poll Service and a derived subject header to Vote Service. Result and vote requests first check poll visibility; a link token must resolve to the requested poll. Browser headers, cookies and arbitrary proxy destinations are not forwarded.

The silent SSO callback alone permits same-origin framing; other served pages retain frame denial. Production static serving includes deep-link fallback, no-cache runtime settings, no-store API responses, MIME sniffing protection and a no-referrer policy. An unavailable upstream produces a recoverable error rather than demo content. The Docker image serves the same build and gateway; there is no separate frontend-only development data mode.

The checked-in OIDC fixture is under `tests/`, binds only to loopback and is never copied into the runtime Docker stage. It deliberately skips production identity-provider guarantees and must not be used for real users. Only the normal Keycloak adapter and API transport are shipped to the browser.

Hosting assumes the origin root. For a subpath or different origin, update runtime config, Keycloak redirect/web origins and gateway origin together. Shared DPoP replay storage, production TLS and private backend networking remain deployment responsibilities.
